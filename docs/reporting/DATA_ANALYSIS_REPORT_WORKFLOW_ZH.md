# 中文数据分析报告工作流

这套工作流用于数值计算、仿真核对和跨软件结果比较。目标不是把报告做得更“像模板”，而是让读者能迅速看懂：比较了什么、结果是多少、为什么会这样，以及哪些结论暂时不能成立。

## 公开实践及本项目采用方式

| 公开实践 | 可复用原则 | 本项目采用方式 |
|---|---|---|
| [GitHub Docs style guide](https://docs.github.com/en/contributing/style-guide-and-content-model/style-guide) | 清楚和准确比形式上的一致更重要；尽量使用主动语态；提醒框应少用 | 正文不使用彩色结论框，不用状态颜色代替解释 |
| [GitHub Docs best practices](https://docs.github.com/en/contributing/writing-for-github-docs/best-practices-for-github-docs) | 使用普通、简短的语言；每个句子只承担一个主要意思；格式只帮助扫读 | 段落先写结果，再写数据依据和限制；粗体只用于必要术语 |
| [The Good Docs Project templates](https://github.com/thegooddocsproject/templates) | 把解释、操作步骤和参考信息分成不同内容类型 | 分析正文、运行说明和来源记录分别存放，不再混写 |
| [Cookiecutter Data Science](https://github.com/drivendataorg/cookiecutter-data-science) | 报告、图、数据和源代码分目录保存 | 输出目录使用 `data/`、`figures/`、报告源文件和 README 的轻量结构 |

这些仓库并没有提供一套可以原样照搬的中文 LaTeX 模板。真正有用的是它们共同强调的内容边界：分析是分析，操作说明是操作说明，审计记录是审计记录。

## 报告正文的固定任务

正文只完成五件事：

1. 说明要回答的计算问题和比较基准。
2. 给出最重要的结果，并说明数值如何计算。
3. 解释结果变化的技术原因。
4. 把不确定性放在受其影响的结果旁边。
5. 用一段话说明目前能够成立的结论。

建议控制在 3--5 页，通常保留 2--3 张表和 1--2 幅必要图片。表用于精确查数，图用于说明几何、趋势或组间比较。没有分析作用的装饰图不进入正文。

## 文件边界

| 文件 | 放什么 | 不放什么 |
|---|---|---|
| `*.tex` / `*.pdf` | 问题、方法、结果、解释、局限和结论 | 代码路径、运行命令、状态码、交付说明 |
| `README.md` | 编译方法、运行入口、目录说明 | 大段结果讨论 |
| `SOURCE_NOTES.md` | 数据来源、文件路径、字段口径和未完成项 | 面向老师的正文 |
| `data/` | 报告实际使用的 CSV 快照 | 临时日志和无关中间文件 |
| `figures/` | 正文实际引用的图 | 调试截图和重复版本 |

## 实际执行顺序

1. 从正式 CSV 或模型输出提取报告所需数值，不从旧 PDF 手抄。
2. 先写一份事实清单，逐条注明比较基准和限制。
3. 按“结果—数据—解释—限制”写每个主要段落。
4. 使用 `humanizer-zh` 的正式模式删去套话，保留数值、公式和限定条件。
5. 使用 `delivery-style-guard` 删除制作过程、脚本路径和对用户说的话。
6. 运行 `tools/reporting/check_data_report.ps1`，修复阻断项和文字警告。
7. 用 XeLaTeX 连续编译两次，随后将 PDF 渲染为图片检查表格、分页和中文字体。

## 文字规则

- 直接写“结果显示”“计算得到”“两者相差”，不用“结论先行”“充分证明”“形成闭环”等口号。
- 一句话尽量只放一个判断。因果关系需要技术依据，不能只用“说明”“表明”连接两个数字。
- 同一概念使用同一个名称，不为避免重复而不断换同义词。
- 数值后紧跟比较对象和单位。百分比必须交代分母或比较基准。
- 不把网格收敛写成跨软件正确性证明，也不把非同构模型差写成数值误差。
- “尚未完成”可以保留，但应紧跟缺少的模型、工况或数据，不写成空泛的后续计划。

## 版式规则

- 不使用 `\fcolorbox`、`\colorbox` 或 `\textcolor` 装饰结论。
- 不在正文设置“通过/部分通过/未完成”交通灯表。
- 不用粗体标出整段话，全文强调内容不超过少量关键词。
- 标题描述本节得到的结果，例如“修正后反推结果与 COMSOL 相差约 1.84%”，避免“结果分析”“情况说明”一类空标题。
- 操作步骤使用编号列表，但只放在 README，不放进分析正文。

## 完成标准

- 正文中的每个主要数字都能在 `SOURCE_NOTES.md` 指向的文件中找到。
- 表格数值、正文表述和结论没有互相矛盾。
- 报告明确区分同构核验、非同构比较和单软件网格收敛。
- 文字检查脚本返回 `PASS`。
- XeLaTeX 编译成功，PDF 逐页渲染后没有溢出、裁切、乱码或空白页。
